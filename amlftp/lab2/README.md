# Мультизадачная классификация: фото и текст

Лабораторная 2. Окружение `uv` общее и лежит в корне репозитория. Команды ниже, кроме сборки Docker, запускаются из каталога `lab2`.

Один товар описывается несколькими метками сразу. Общий cross-attention читает фото и название, а отдельные головы предсказывают категорию, пол, сезон и назначение. Головы «только фото» и «только текст» модальности не смешивают и нужны для сравнения в отчёте.

## Задачи и данные

Датасет [`ashraq/fashion-product-images-small`](https://huggingface.co/datasets/ashraq/fashion-product-images-small). Поля входа: `image`, `productDisplayName`. Строка остаётся в выборке, только если все четыре метки входят в списки ниже.

- `masterCategory`: Accessories, Apparel, Footwear, Personal Care
- `gender`: Boys, Girls, Men, Unisex, Women
- `season`: Fall, Spring, Summer, Winter
- `usage`: Casual, Ethnic, Formal, Sports

Редкие значения `usage` (Smart Casual, Party, Travel, Home) отбрасываются вместе со строкой. На класс `masterCategory` берётся не больше 1500 примеров. Разбиение 70/15/15 стратифицировано по `masterCategory`.

Фотографии в датасете — миниатюры около 60 px. Энкодер получает их в размере 224 px, визуальные токены ResNet-18 образуют сетку 7×7.

## Модель

Замороженные ResNet-18 и DistilBERT выдают последовательности токенов. Обучаются общие проекции и два блока `MultiheadAttention`. Каждая задача получает свою линейную голову на усреднённых выходах attention, а не на склейке исходных эмбеддингов:

- изображение → текст: запросы — клетки фото, ключи и значения — токены названия;
- текст → изображение: запросы — токены названия, ключи и значения — клетки фото.

Функция потерь — сумма cross-entropy по четырём задачам без весов. Та же сумма считается для унимодальных голов и добавляется к потере fusion, чтобы базовые головы тоже учились. Лучший чекпоинт выбирается по среднему val macro-F1 fusion. Паддинг названия маскируется. Веса общего attention рисуются в отчёте и в Gradio.

Каталог `weights/` после обучения содержит `model.pt` (лучшие веса), `last.pt` (состояние для возобновления), `resnet18.pt`, `distilbert/` и кэш токенов. Эти веса несовместимы с лабораторной 1: у голов другие размеры. Демо читает каталог `lab2/weights` и не скачивает энкодеры заново.

`train.py` берёт кэш Hugging Face из `lab1/data/hf`, если этот каталог уже есть, иначе из `lab2/data/hf`.

## Запуск и воспроизведение

Seed фиксируется в начале `train.py` до загрузки выборки, разбиения и инициализации модели.

### 1. Окружение

Из корня репозитория:

```shell
uv sync --locked
```

### 2. Тесты и типы

```shell
uv run --project .. pytest
uv run --project .. mypy src
```

### 3. Обучение с нуля

```shell
uv run --project .. train.py --seed 42 --epochs 5 --max-per-class 1500 --weights-dir weights
```

Первый запуск при отсутствии кэша скачивает датасет, ResNet-18 и DistilBERT, сохраняет энкодеры в `weights/` и учит общий cross-attention вместе с головами задач. Повторный запуск с тем же seed использует кэш токенов. Если сборка PyTorch не видит GPU, обучение идёт на CPU.

### 4. Возобновление

`weights/last.pt` хранит веса, оптимизатор, номер эпохи, историю, seed, списки классов задач и состояния генераторов случайных чисел. Команда продолжает обучение со следующей эпохи до `--epochs`. Если в чекпоинте другой seed или другие списки классов, скрипт останавливается.

```shell
uv run --project .. train.py --seed 42 --resume weights/last.pt --epochs 5 --weights-dir weights
```

Чтобы доучить модель дальше, увеличьте `--epochs`, оставив тот же `--seed`.

### 5. Отчёты и веса

После обучения появляются:

- `reports/report.md` и `reports/report.html` — по каждой задаче метрики fusion и унимодальных голов, кривые среднего и позадачного macro-F1, матрицы ошибок и примеры со всеми четырьмя метками;
- `weights/model.pt` — лучшие веса по среднему val macro-F1 для демо;
- `weights/last.pt` — чекпоинт возобновления;
- `weights/resnet18.pt` и `weights/distilbert/` — замороженные энкодеры.

### 6. Демо

```shell
uv run --project .. gui.py --weights weights
```

Интерфейс Gradio открывается на порту 7860. Нужны фото и название. Четыре блока показывают вероятности задач. Если отчёт уже построен, подставляются примеры из `reports/examples`.

### 7. Docker

Образ не содержит веса: каталоги `weights/`, `reports/` и `data/` исключены через `.dockerignore`. Сборка идёт из корня репозитория. Точка входа принимает режим `gui` или `train`. Без аргумента запускается `gui`.

```shell
docker build -f lab2/Dockerfile -t amlftp-lab2 .
```

Демо читает веса только на чтение. Если `model.pt` нет, процесс завершается с ошибкой и не создаёт файлы в этом каталоге.

```shell
docker run --rm -p 7860:7860 -v "$PWD/lab2/weights:/weights:ro" amlftp-lab2 gui
```

Обучение пишет чекпоинты в `/weights`, отчёты в `/reports`, а датасет ищет в `/app/data`. Внутри контейнера нет каталога `lab1`, поэтому кэш монтируется из лабораторной 1. Seed по-прежнему задаётся до разбиения выборки.

```shell
docker run --rm \
  -v "$PWD/lab2/weights:/weights" \
  -v "$PWD/lab2/reports:/reports" \
  -v "$PWD/lab1/data:/app/data" \
  amlftp-lab2 train --seed 42 --epochs 5 --max-per-class 1500
```

Возобновление внутри контейнера читает `/weights/last.pt`. Другой `--seed` останавливает запуск.

```shell
docker run --rm \
  -v "$PWD/lab2/weights:/weights" \
  -v "$PWD/lab2/reports:/reports" \
  -v "$PWD/lab1/data:/app/data" \
  amlftp-lab2 train --seed 42 --resume /weights/last.pt --epochs 5
```
